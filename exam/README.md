# 기출문제 처리기

**문제지 파일을 `exam/papers/` 에 올리면, 밀어 넣은 그 순간 알아서 처리한다.**
사람이 스크립트를 돌리지 않는다.

```
exam/papers/ 에 PDF·HWP 를 push
        ↓  (GitHub Actions 가 push 를 신호로 깨어난다)
   문항 추출  →  열람용 HTML 생성  →  결과 확인  →  결과를 레포에 되커밋
        ↓
exam/out/questions.json   기계가 읽는 구조화 데이터
exam/out/index.html       사람이 보는 페이지 (검색·교시 필터)
```

## 왜 이 형태인가

`mfind` 는 이 레포 최상위 README 5장에서 스스로 **"지금 이것은 도구다"** 라고 적고,
에이전트가 되려면 ① 스스로 깨어나기 ④ 보고하기가 없다고 남겨 두었다.
이 처리기는 그 두 칸을 채운 형태다 — **push 가 트리거이므로 사람이 누르지 않아도
돌고**, 결과를 레포에 되커밋하므로 **다음에 열었을 때 이미 정리되어 있다.**

여전히 하지 않는 것도 분명하다. **원본 문제지를 고치거나 지우지 않는다.**
읽고, 구조화하고, 새 파일로 내놓는 것까지가 범위다. 입력을 건드리는 자동화는
틀렸을 때 되돌릴 수 없다.

## 넣는 것

`exam/papers/` 에 문제지 파일을 둔다. **파일명에 `NNN회` 가 들어 있어야** 회차를
인식한다. `(YYYY년)` 이 있으면 시행연도까지 함께 표기된다.

```
exam/papers/제110회 정보관리기술사(2016년).pdf
exam/papers/★제139회 정보관리기술사 문제지.pdf
exam/papers/제116회 정보관리기술사(2018년).hwp
```

## 나오는 것

`questions.json` 은 회차를 키로 하는 구조다.

```json
{ "papers": { "139": {
    "round": 139, "year": null, "source": "★제139회 ....pdf",
    "gyosi_estimated": true,
    "period1": [[1, "WBS(Work Breakdown Structure) 작성방법"], ...],
    "essay": [{ "gyosi": 2, "items": [
        { "no": 1, "stem": "AI 리스크에 대하여 다음을 설명하시오.",
          "subs": [["가", "AI 리스크 개념"], ["나", "AI 보안 리스크"]] },
        { "no": 4, "stem": "...", "subs": [], "spec": "학점(Grade) 처리 모듈 ..." }
    ]}]
}}}
```

## 문제지를 읽으면서 부딪힌 것

파싱이 단순 정규식으로 끝나지 않은 지점만 적는다.

### 양식이 세 가지다

| 양식 | 1교시 안내문 | 해당 |
|---|---|---|
| 신 | `※ 총 13문제 중 10문제를 선택하여 설명하시오` | 133회 이후 |
| 구 | `※ 다음 문제 중 10문제를 선택하여 설명하시오` — **문항 수가 없다** | 110~132회 |
| HWP | 안내문이 표 안에 있어 **텍스트에 잡히지 않는다** | 116회 |

HWP 는 안내문을 못 찾으므로 **문항 번호가 1로 되돌아가는 지점**을 교시 경계로 쓴다.

### 교시 번호가 없는 문제지가 있다

110~127회는 헤더에 `제 N 교시` 가 찍혀 있다. **128회 이후는 없다.**

쪽 번호가 교시인 줄 알았는데 아니었다 — `2 - 1` 은 **「총 2쪽 중 1쪽」** 이다.
그래서 표기가 없는 회차는 **수록 순서를 교시 순서로 본다.** 근거는 표기가 있는
15개 회차 **전부에서 교시 번호가 수록 순서와 일치**한다는 것이고, 추정한 회차는
`gyosi_estimated: true` 로 표시해 결과물에도 `추정` 이 붙는다.
**확인된 것과 추정한 것을 섞지 않는다.**

### 별지와 안내문이 엉뚱한 문항에 붙는다

문제 하나가 `[명세]` 별지를 참조하는데 그 별지는 **다른 쪽에 인쇄**되어 있다.
순서대로 읽으면 마지막 문항 꼬리에 붙는다. 그래서 별지를 따로 떼어 **`아래 명세` 를
참조하는 문항에 연결**한다. 다음 교시 안내문이 6번 문항에 붙는 것도 같은 이유로 잘라낸다.

## 직접 돌려보기

```sh
pip install pypdf pyhwp six olefile      # HWP 를 안 쓰면 pypdf 만으로 충분
python3 exam/tools/extract.py            # exam/papers → exam/out/questions.json
python3 exam/tools/render.py             # questions.json → exam/out/index.html
```

| 옵션 | 뜻 |
|---|---|
| `--papers DIR` | 문제지 위치 (기본 `exam/papers`) |
| `--out FILE` | 결과 경로 |
| `--strict` | 문항 수가 안 맞는 경고가 하나라도 있으면 실패로 처리 |

한 파일이 깨져도 나머지는 처리하고, 실패한 파일은 표준오류로 따로 알린다.
문항 수가 기대(1교시 13, 교시별 6)와 다르면 그 회차 옆에 경고가 붙는다.

## 확인한 것

28개 회차(110~139회, 112·115회 미보유)를 넣어 **868문항**(1교시 364 + 논술형 504)을
경고 없이 추출했다. 열람용 HTML 은 표준 모드로 렌더링되고 검색·교시 필터가 동작하며
휴대폰 폭에서 가로 스크롤이 생기지 않는다.

## 하지 않는 것

- **문제지를 받아오지 않는다.** Q-Net 자료실에서 내려받는 것은 사람 몫이다.
- **답안을 만들지 않는다.** 문항을 구조화하는 데까지가 범위다.
- **Pages 에 배포하지 않는다.** 이 레포의 Pages 는 `web/` 의 mfind 데모가 쓰고 있다.
  결과 HTML 은 레포에 커밋만 하고, 볼 때는 내려받아 열거나 별도로 올린다.
